# 图片类型：基础／拉伸

图片图元使用 `imageType: "basic" | "stretch"`。至少一条 `m_Border` 大于零的素材支持基础／拉伸，新增及缺少类型的导入图片默认拉伸；边界全零或缺失的素材只支持基础，右侧「图片类型」只显示基础并禁用切换。JSON、收藏素材和 WebMCP 的 `add_element` / `update_element` 保留此字段。支持拉伸的图片若已明确选择基础，保留该选择；切换素材 ID 且未指定类型时按新素材重新取默认值。不支持拉伸的图片即使导入或工具请求指定拉伸，也统一改为基础。

基础按图元尺寸缩放整张贴图。拉伸按 sprite 的边界做三切片或九切片：四角保留尺寸，边缘沿一个方向伸长，中间沿两个方向伸长。查看背景与图元尺寸不参与边界换算，不乘 2/3。

## 边界和导出

边界来自图片库 `/border/<id>.json` 的 `m_Border`：X=左、Y=下、Z=右、W=上。按原始数值直接使用，宽高来自 `m_Rect`。目标尺寸小于一对边界的总和时，按比例缩小这对边界以避免重叠。边界为零或不存在时按整图缩放。

106030 的原图为 90×90，四边均为 45。因此 407.50×265 的目标分界为 X=[0,45,362.5,407.5]、Y=[0,45,220,265]。源中心的宽高为零，仍需重复接缝的采样值来绘制直边及中间区域，不能丢弃这些切片。

画布使用 SVG 切片预览；PNG 使用同一边界的网格采样，并保留染色、透明度和旋转。CSS/SVG 导出将当前尺寸的拉伸结果内嵌为 PNG，同时保存素材 ID、类型与颜色，回导时恢复图片图元。脱离编辑器直接修改 CSS/SVG 的图片宽高只会缩放该内嵌位图；需要重新切片时应回导后再导出。

2026-10-11 检查的 [data.json](https://oss.070077.xyz/images/data.json) 包含 1543 个图片条目，每个条目只有 `id`、`img`、`border`；分类也只记录 ID 和图片列表，没有明确的拉伸支持标志或基础／拉伸默认值。所有条目都有 `border` 文件链接，因此不能仅凭链接存在判断支持拉伸。项目按用户指定的规则读取 `m_Border`：任一边界大于零即支持且默认拉伸，全零或缺失时只支持基础。例如 106030 四边均为 45，默认拉伸；100001、105222 四边均为零，只支持基础。这是项目采用的默认规则，不是 `data.json` 提供的默认类型字段。

前端使用按素材 ID 缓存的元数据统一处理新增、拖入、收藏、素材替换与撤销／重做。元数据尚未加载时不提前写死基础默认值，切换控件暂时禁用。后端所有导入／导出接口也应用同一规则，单次请求内去重并复用边界数据；元数据文件不存在时使用基础，上游读取失败时报告错误，避免误判素材能力。

Lua 在图片数据区增加与 `ELEMENTS` 对齐的 `IMAGE_TYPES`，通过 `Enum.ImageType.Basic` / `Stretch` 设置。按客户端 API 的限制使用 `pcall`，不支持该类型的图片可能保留模板状态。没有 `IMAGE_TYPES` 的旧 GIA 绘图 Lua 继续按其原先的 Stretch 行为回导。上游 Lua 运行时文件保持原样，设置由应用适配层替换。

## GIA 字段证据与推测

用户提供的客户端控件样本 `基础&拉伸图片gia.gia`（声明版本 7.1.0，resource class=70）含两个相同的 106030 图片，尺寸均为 80×80。其基础／拉伸差异为：

```text
graphs(1).ui(19).content(1).data(505)[field502=96]
  .details(503).image_slot(84).field504
基础：省略（默认 0）
拉伸：varint 1（字节 c0 1f 01）
```

另一个资源槽 `image_slot(85)` 的 `field507=2` 在两者中相同，不能当作图片类型字段。

项目素材组模板声明版本为 6.5.0、resource class=15，使用另一套布局：

```text
content.data(505)[field502=38].details(503).image_settings(31)
2 = 图片资源 ID
3 = source_meta
4 = ARGB 颜色
6、10 = 空消息
```

用户授权参考客户端样本推测素材组字段。本项目尝试在这一旧结构中用 **`image_settings.field5=1`** 表示拉伸，基础继续省略字段 5。**该映射尚未由素材组导出样本或游戏回导证实**；编码与测试只验证字段的写入，不能证明游戏会采用它。客户端字段 504 也不能直接移植到旧结构。若游戏忽略此字段，需要以素材组的基础／拉伸对照 GIA 修正编码。
